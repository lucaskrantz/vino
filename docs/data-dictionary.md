# Data dictionary

All generated JSONL records carry `schema_version: "1.0"`. Paths below are defaults.

## Raw source

### `data/raw/systembolaget/products.ndjson`

Unmodified-in-meaning product objects emitted by the pinned upstream CLI. The adjacent `manifest.json` records retrieval time, the four subtype commands, filters, adapter version, row counts, exclusions, and SHA-256 hashes.

The source payload is intentionally not treated as stable. Normalization extracts only fields needed by this study.

## Normalized products

### `data/interim/products.jsonl`

| Field | Meaning |
|---|---|
| `product_id` | Stable join key supplied by Systembolaget |
| `product_number` | Customer-facing article number, if present |
| `name`, `subtitle`, `producer` | Product descriptors |
| `country` | Systembolaget-reported origin; unrestricted in the cohort |
| `category` | Exactly `Vin` in the included cohort |
| `wine_type` | Exactly red, white, rosé, or sparkling (`categoryLevel2`) |
| `wine_subtype` | API category level 3 |
| `vintage` | Declared vintage, nullable |
| `assortment` | Assortment description |
| `price_sek` | Current package price |
| `volume_ml` | API package volume |
| `price_per_750ml_sek` | `price_sek × 750 / volume_ml` |
| `alcohol_percentage`, `is_organic` | Potential covariates |
| `product_launch_date` | API launch timestamp |
| `images` | Base image URLs and available rendition widths |

## Images

### `data/interim/images.jsonl`

One record per downloaded product image: `product_id`, zero-based `image_index`, source image base URL, final source URL, local path, selected rendition width, detected media type, byte count, SHA-256, and retrieval timestamp.

The downloader first tries the highest advertised direct WebP rendition not exceeding the requested width, then the Systembolaget image proxy. File signatures are checked because the CDN may use a generic content type. Resume reuses a local file only when its hash, rendition width, and source base URL still match the current product snapshot. Individual failures are appended to `data/interim/image_errors.jsonl`; the batch continues, and a later run retries only images that still lack valid manifest records.

## Vision output

### `data/interim/vision_results.jsonl`

Append-only records keyed by product, image index, image hash, model, and prompt version.

| Field | Meaning |
|---|---|
| `provider`, `model`, `response_id` | Model and API provenance |
| `prompt_version`, `image_detail` | Version of the coding instructions and requested image resolution |
| `input_tokens`, `output_tokens`, `total_tokens`, `cost_usd` | Provider-reported usage when available |
| `assessed_at` | UTC completion timestamp |
| `assessment.label_visibility` | `good`, `partial`, or `unreadable` |
| `assessment.animal_presence` | `present`, `absent`, or `uncertain` |
| `assessment.detections` | Common name, taxon group, depiction style, confidence, evidence |
| `assessment.confidence` | Overall 0–1 confidence |
| `assessment.needs_review` | Model review recommendation |
| `assessment.notes` | Brief ambiguity note |

Failures are appended separately to `data/interim/vision_errors.jsonl` and are not converted to absent labels.

## Human review queue and input

### `data/manual/review_queue.csv`

Generated by `vino review-queue`. By default it contains uncertain, model-flagged, and low-confidence results, with local image path, AI provenance, reason, and evidence. `--include-all` exports every result for audit sampling. AI labels are proposals, not completed reviews.

### `data/manual/reviews.csv`

Required columns are shown in `reviews.csv.example`; the generated queue already contains them plus optional context columns. Lists use semicolons. A reviewer must fill `reviewer` and `reviewed_at` and verify/correct the label fields. `image_sha256` binds a correction to the AI-classified image and current image manifest; a missing result or hash mismatch fails analysis. Human labels override AI labels for that image while raw AI records remain intact.

## Vivino lookup and score data

### `data/external/vivino_lookups.jsonl`

One append-only lookup result per queried Systembolaget product and matcher version. It records the exact query and wine-type filters, status (`matched`, `needs_review`, `no_match`, or `error`), target identity, selected candidate, alternative candidates, response hash, retrieval time, and endpoint.

Each candidate retains Vivino wine/vintage IDs, name, winery, year, country/region, vintage and across-vintage ratings/counts, source URL, identity subscores, combined confidence, vintage agreement, and hard conflicts. `matched` means the wine identity passed the configured threshold; it does not mean that an exact-vintage score exists.

### `data/external/vivino_quality_scores.csv`

Primary export generated by `vino export-vivino-scores` in the generic score format below. Additional columns preserve `review_count`, `score_scope` (`vintage` or `wine`), match confidence, source record IDs, and matched Vivino identity. The current artifact contains 598 products: 509 exact-vintage records and 89 wine-scope records for listings without a declared target vintage.

### `data/external/vivino_quality_scores_wine_level.csv`

Sensitivity export generated with `--allow-wine-level`. The current artifact contains 1,033 products: 509 vintage-scope and 524 wine-scope records. The wine-scope fallback for a vintage-dated product is an across-vintage community average and must be labeled accordingly.

### `data/manual/vivino_identity_reviews.jsonl`

Append-only accept/reject adjudications for ambiguous Vivino identities. Each decision is bound to product ID, matcher version, and the SHA-256 of the exact lookup response. Accepted decisions also bind Vivino wine/vintage IDs and candidate rank. Reviewer, method, model, prompt version, response ID, confidence, reason, notes, and timestamp preserve whether a decision was human, AI-assisted, or image-audited. A stale hash or missing candidate makes export fail rather than silently applying an old decision.

AI-assisted decisions are not human validation and must be described as such. The exporter consumes the latest decision per product only when `--identity-reviews` is supplied.

See [Vivino source review](vivino-source-review.md) for endpoint caveats and the corrections made to the reviewed Home Assistant implementation.

## External score input

### `data/external/quality_scores.csv`

| Field | Meaning |
|---|---|
| `product_id` | Exact cohort join key; unique in the CSV |
| `quality_score` | Raw external score |
| `scale_min`, `scale_max` | Declared bounds used for normalization |
| `score_source` | Source/panel name |
| `observed_at` | Score observation date |
| `source_url` | Auditable record URL, when available |
| `review_count` | Optional number of contributing ratings |
| `score_scope` | Optional scope such as exact `vintage` or across-vintage `wine` |
| `match_confidence` | Optional 0–1 entity-match confidence |
| `source_record_id` | Optional stable source identifier(s) |

The loader rejects duplicate IDs, impossible scales, and out-of-range scores. The final research dataset preserves all optional score provenance columns.

## Analysis outputs

### `data/processed/research_dataset.csv`

Primary one-row-per-product analysis dataset. It combines product fields with product-level animal state, semicolon-separated names/groups, classification provenance, and raw/normalized external score fields. `animal_names` preserves normalized specific detections (for example `red fox` or `eagle`), while `animal_categories` provides the stable frontend groupings `lion`, `pig`, `deer`, `bird`, `horse`, and `fox`. Categories are non-exclusive; bird membership is derived from the reviewed taxonomic group rather than a manually maintained species list.

Product-level state is present if any image is present; absent only if every expected image is absent; otherwise uncertain.

### `data/processed/research_dataset_wine_level.csv`

Sensitivity counterpart generated from the across-vintage score export. Its score-scope column must remain visible to downstream consumers.

### `reports/summary.json` and `reports/report.md`

Primary cohort flow, descriptive group statistics, animal-minus-no-animal mean differences, bootstrap intervals, permutation p-values, methods, and mandatory interpretation warnings. Individual animals and taxon groups are non-exclusive, so their counts can sum beyond the number of animal-present products. The Markdown report ranks individual animal imagery by mean standardized price and mean normalized score; sparse ranks remain exploratory.

### `reports/summary_wine_level.json` and `reports/report_wine_level.md`

The equivalent sensitivity outputs using the across-vintage score fallback. They must not silently replace the primary files in publication-facing code.

## Frontend data

`scripts/build-web-data.mjs` reads both processed research datasets and the frozen source manifest, validates cohort agreement, and writes `src/data/generated/production-data.ts`. The generated module contains primary and sensitivity rankings, score distributions, product-level explorer records, preserved specific-animal names, stable frontend categories, and real label-example metadata. `src/data/generated/build-manifest.json` records SHA-256 hashes for every source and the output plus the frozen display rule (at least 10 scores and 30% coverage).
